
Нормализация исходных рыночных данных
=====================================


Назначение документа - техническое задание на этап нормализации исходных рыночных данных.
Правовая база работы с рыночными данными: `docs/market-data-regulation.md`.


Предпосылки нормализации
------------------------

Данные приходят из разрозненных источников (разных бирж) в различных форматах и архивах (CSV, JSON, custom, zip, gz), чтобы постоянно не переписывать основной программный модуль под новые или изменившиеся старые данные, требуется предварительная нормализация.


Как это должно работать
-----------------------

Выбранные источники и ссылки для скачивания данных: `data\sources\download.txt`.
График обновления приведенных источников: `data\sources\availability.txt`.

Каждый день обновленные данные скачиваются из указанных источников в соответствующие каталоги. Каждый файл данных содержит торговую сессию за один день, время указывается в UTC.

На момент составления этого документа структура каталогов с источниками выглядит так:

/data
    /sources
        /BOAG Borsen AG
            /Borse Dusseldorf (DUSA, DUSB)
            /Borse Dusseldorf Quotrix (DUSC, DUSD)
            /Borse Hamburg (HAMA, HAMB)
            /Borse Hamburg Electronic Trading 2 (HAMP, HAMQ)
            /Borse Hannover (HANA, HANB)
        /Deutsche Borse Group
            /Borse Frankfurt (source - DFRA)
            /Eurex (source - DEUR)
            /Tradegate BSX (source - DGAT)
            /Xetra (source - DETR)
        /Equiduct (XEQT)
        /LS Exchange (HAMN)

В каталоге `data/sources/` должен находиться пакетный файл `normalize.cmd`, который запускает питон-скрипты `normalize.py` в каталогах-источниках.

Пакетный файл запускает все вложенные скрипты по очереди.
Эти скрипты обрабатывают все файлы с данными в папке источника.
Для каждого файла данных скрипт `normalize.py` должен:
- считать файл в память
- исключить:
    - записи не входящие в указанную дату (такие глючные "хвосты" с прошлой даты иногда попадаются)
    - заявки
    - котировки bid/ask
    - служебные события
    - индикативные и справочные цены
    - записи без действительной цены или с нулевым объёмом сделки
    - дубли по идентификатору сделки
    - сообщения об отмене и соответствующие им исходные сделки
    - пустые строки без данных
    - невалидные записи и записи, которые не удалось разобрать или классифицировать
- обработать и применить исправления сделок
- отсортировать сделки по времени исполнения, для одновременных сохранить порядок источника
- сохранить результат в симметричную папку `data/normalized/<source_path>/YYYYMMDD.csv.zip`
- удалить исходный файл с данными

Все сомнительные решения следует фиксировать в одноименный лог: `YYYYMMDD.log.zip`.

Смысл обработки - оставить только записи, необходимые для формирования OHLCV свечей.
На этом процесс нормализации завершается.

Наличие нормализованного файла за некоторую дату является свидетельством произведенной нормализации, поэтому дополнительной фиксации в документации или реестре не требуется.

При необходимости архив исходных данных следует вести отдельно.


Целевой формат данных
---------------------

Обязательные поля записи:

- источник
- площадка/MIC
- идентификатор инструмента
- время исполнения
- цена
- объём
- единица объёма

Время указывается в UTC.
